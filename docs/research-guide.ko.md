# NST 0.20.0 연구팀 마법사 설치 안내

현재는 **로컬 후보 버전**입니다. 모의 검사와 실제 연구 완주를 구분하세요.
[이번 수정·검증 결과](verification-0.20.0.md)를 먼저 확인하세요.

1. NST 연구팀 ZIP을 짧은 새 폴더에 전부 풉니다. 예: C:\\NSTResearch020.
   Start-HermesResearchSetup.cmd를 실행합니다.
2. **로컬 서버**에서 Docker Desktop의 Linux 엔진 준비를 확인합니다.
   관리자 계정·팀·채널을 정하고 생성에 동의합니다. 기존 서버와 같은 대상을 덮어쓰지 않습니다.
   WSL2·Windows 기능·Docker 약관·재부팅이 필요하면 사용자가 확인해야 합니다.
3. **Hermes·모델**에서 검증 설치 또는 '기존 Hermes 사용'을 고릅니다.
   기존 사용은 개인 파일과 인증을 삭제하지 않습니다. 현재 모델 인증과 선택 모델을 확인합니다.
4. **3. 에이전트 4개** 최상단 카드에서 모델·작업 폴더·기본 한도를 확인합니다.
   모델·웹 전송 및 실제 설치 테스트 동의는 자동으로 체크하지 않습니다.
   같은 창에서 1단계에 입력한 관리자 비밀번호는 이어집니다. 창을 새로 열었다면 다시 입력합니다. 비밀번호를 로그나 평문 파일에 저장하지 않습니다.
   이름·토큰·모델·작업 폴더·한도는 접힌 **세부 설정 보기·변경**에서 나중에 바꿀 수 있습니다.
5. 최상단 **기본설정 자동 구성 · 실제 설치 검증**을 한 번 누릅니다.
   네 봇·토큰 발급/재사용 → 전체 페르소나 → 개인 Gateway와 연구 프로필 격리 → 독립 실행기 → 한국어 보드·NST 플러그인 → 실제 S1·S2·S3 순으로 진행합니다.
   플러그인 적용 중 Mattermost는 잠시 재시작되며 계정·대화·첨부파일은 보존합니다.
   모델 구독 사용량이 발생하고 자료 접근·모델 장애에 따라 오래 걸릴 수 있습니다.
6. '사용 준비 완료'는 모든 실제 검증 증거가 있는 경우에만 표시합니다.
   pending/미완료는 설치 전체가 사라졌다는 뜻이 아닙니다. 같은 설정으로 저장된 요청을 확인하고 이어갑니다.
   기존 기록을 삭제하거나 요청을 중복해서 여러 번 보내지 마세요.

이미 로컬 서버와 네 봇을 만들었다면 삭제하거나 서버를 새로 만들지 않습니다. 1단계에서 기존 서버 기록을 불러오고 2단계의 기존 Hermes를 확인한 후, 3단계 버튼으로 같은 봇·토큰을 재사용합니다.

이미 설치·검증을 끝내고 보드와 브랜딩만 추가하려면 3단계의 **설치된 연구팀에 보드·NST만 연결**을 누릅니다.
이 버튼은 연구팀을 재구성하거나 S1·S2·S3을 재실행하지 않습니다. 진행 중인 연구가 없는 때 적용하세요.
[접근 권한과 복구 안내](mattermost-plugins.ko.md)

## 평소 사용

Mattermost의 연구 채널에서:
> @research-lead RAG 관련 연구를 시작하려고 해. 기존 접근법의 방법·데이터·성과·한계를 원문 근거와 비교한 Word 문헌검토 보고서를 만들어줘. 참고문헌과 후속 연구 질문도 포함해줘.

사용자는 원하는 결과물만 요청합니다. 역할별 지시·JSON·보드 파일을 직접 작성하지 않습니다.
Mattermost 왼쪽 **연구 작업보드**를 누르면 채널 옆 내부 화면에서 프로젝트·작업·중간 문서·감사·사용자 확인 요청·실시간 기록을 봅니다.
보드는 읽기 전용입니다. 상태 질문이나 결정·추가 자료 전달은 같은 스레드에서 총괄을 멘션합니다.

## 다시 설치하기 전에

마법사 소유의 기존 연구팀만 전환 동의와 검증 후 처리합니다.
개인 프로필, 인증, 다른 서버를 삭제하는 기능을 이 설치 흐름에 넣지 않았습니다.
새 후보를 검사할 때는 독립 Windows 환경을 권장합니다.
소스 복사본을 만들었다는 것과 설치 런타임이 자동으로 격리된다는 것은 다릅니다.
