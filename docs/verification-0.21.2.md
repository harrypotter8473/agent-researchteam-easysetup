# 0.21.2 필수 검증 복구

## 변경

완료 카드와 필수 검증 통과를 구분합니다. 마지막 작업 결과 뒤에도 현재 중간·최종 감사,
필수 파일과 설치 검증기가 관찰한 실패를 요청/스레드 단위로 확인합니다.
누락이 있으면 총괄에게 변경된 파일 해시·반려 사유를 전달하고 실제 역할 실행기로 수정·재감사를 진행합니다.
총괄에게 주는 정보는 진단이지 승인이나 새 사용자 권한이 아닙니다.

중간감사와 최종감사를 합치거나, `done`을 감사 통과로 보거나, 누락 플래그를 강제로 바꾸지 않습니다.
수정 담당자는 원본 작성자 역할이며 감사자는 블라인드 사본에서만 검증합니다.
대체 작업의 중간감사는 같은 역할·같은 필수 파일을 실제 현재 해시로 검증한 경우에만 인정합니다.

## 지속성과 한도

- 복구 의도·검증 관찰: 연구 runtime의 `run/validation-requests/` (Git 원격+요청 스레드별).
- 실제 복구 상태·호출 수·누락 검사: `run/lead-coordinator.json`의 `validation:` 항목.
- 검증 관찰은 해당 Git tree에서만 유효하며, 긍정 관찰 자체로 감사 게이트를 열지 않습니다.
- 실제 작업 카드·원장·감사 영수증은 원래 프로젝트의 `.tasks/`와 Git에 그대로 남습니다.
- 실행 중/실행 대기 작업이 있으면 추가 복구 호출을 하지 않습니다. 명시된 사람 확인·수동 실험 재개는 존중합니다.
- 기존 task/model/time 한도를 유지합니다. 복구는 요청당 기존 MAX_ATTEMPTS 안에서만 호출하고,
  같은 누락 검사·실제 파일 해시가 3회 연속 바뀌지 않으면 구체적인 보류 사유를 남깁니다.
  연결 backoff 대기나 단순 상태 조회는 새 호출로 세지 않습니다. 재시작해도 횟수는 유지합니다.
- 원장 무결성 실패는 자동 덮어쓰지 않습니다. 인증 실패·구체적인 사용자 입력·반복 무진전은
  마법사에 누락 검사와 기록 경로를 표시합니다. 원인을 해결한 뒤 관리자가
  `research_board.py coordinate --retry-paused`로 명시적으로 재개할 수 있으며 총 호출 수는 초기화하지 않습니다.
- 이미 통과한 과거 요청은 다른 보고서의 새 파일 때문에 자동으로 다시 실행하지 않습니다.

## 검증 구분

무료 검사 `tests/test_validation_recovery.py`는 실제 파일·버전별 영수증·로컬 Git으로
중간감사 무효화+반려+최종감사 통과+모든 카드 완료 상태를 재현합니다.
양성 관찰로 승인 불가, 스레드 분리, 수정 역할·파일 대조, 실행/사용자 결정 존중,
재시작 후 복구 한도 유지, 반복 첨부 방지 등을 검사합니다.

`tests/test_validation_suite_flow.py`는 실제 설치 검증 루프·Git 보드·블라인드 사본·감사 실행기·
파일 검증·로컬 HTML HTTP 확인을 사용합니다. S1/S2/S3 각각에 같은 감사 누락을 넣고,
새 중간감사가 통과하기 전 다음 시나리오가 시작되지 않으며 통과 후 S1→S2→S3가 이어지는지 검사합니다.
이 검사의 모델·Mattermost 응답은 대체한 것이므로 **실모델 또는 새 PC 설치 통과 증거가 아닙니다.**
테스트 임시 `live-test.json`을 운영 runtime으로 복사하지 않습니다.

2026-10-23 로컬 무료 회귀 결과: Python 176개 통과, Windows PowerShell 5.1/7 각각
20개 회귀 묶음과 통합 마법사 GUI 통과, 배포 검증 106개 통과, Node 보드/플러그인 검사와
Go 플러그인 서버 검사 통과. 이 수치에는 실모델 성공을 포함하지 않습니다.

전체 검사 후 비-S1 필수 검사(numeric/html/roles/lead_delivery/custom) 진단 1개를 추가했고,
해당 복구 검사 14개와 모의 전체 전환 검사를 다시 통과했습니다.

## 범위와 남은 한계

- 이번 실제 실행은 후보 payload·설치기의 프로필/작업 폴더 구성 함수·독립 실행기·모델·실제 Mattermost를 연결한 검사입니다.
  기존 서버 설정·기존 채널/대화·운영 서비스/프로필·개인 인증은 교체하지 않았습니다. 검증용 서비스만 종료했고 기록은 보존했습니다.
- 별도 Hermes home의 관리 launcher 초기 의존성 준비가 지연되어, 실험에만 설치기가 지원하는 공식 native Python/shared Hermes 진입 어댑터를 사용했습니다.
  이 어댑터·인증·runtime은 제품 소스나 ZIP에 포함하지 않습니다. 새 Windows PC의 전체 bootstrap/설치를 통과했다는 뜻이 아닙니다.
- 누락/변경/반려 중간감사와 최종감사 불일치를 고의 주입한 복구는 앞 절의 무료 회귀에서 검증했습니다.
  실제 모델 연속 실행은 정상 감사·후속 배정·전환·전달을 검증했으며, 같은 장애를 실모델에 고의 주입한 별도 성공으로 주장하지 않습니다.
- Word 내용·구조·해시 및 독립 감사는 확인했으나 최종 Word의 모든 페이지를 화면 렌더링한 시각검증은 하지 않았습니다.
- 로컬 검사·실모델 결과는 원격 GitHub Actions 통과나 모든 사용자 PC의 설치 성공을 대신하지 않습니다.
  게시 커밋의 CI·배포 ZIP/SHA는 별도로 확인합니다. 현재 배포는 미서명 프리릴리스입니다.
