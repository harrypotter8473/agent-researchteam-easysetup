# 0.17.2 수정·검증 — 2026-10-21

## 변경

- 3페이지 최상단에 원클릭 기본설정·실제 설치 검증 버튼을 배치했습니다. 네 봇·토큰 발급/재사용, 원본 페르소나, 연구 Gateway 격리, 독립 실행기, S1·S2·S3 검증을 기존 완료 이벤트로 이어갑니다. 이 버튼이 검증을 생략하거나 완료 판정을 미리 만들지는 않습니다.
- 접힌 세부 설정에서 이름·토큰·모델·작업 폴더·한도를 변경할 수 있습니다. 실제 모델·웹 전송·설치 동의는 자동으로 선택하지 않습니다.
- 1단계 관리자 비밀번호를 지우기 전에 같은 창의 3단계에 연결합니다. 창을 닫으면 지우며, 새 창에서 이전 비밀번호를 평문 파일로 복원하지 않습니다.
- 현재 설치된 Hermes는 `gateway.multiplex_profile_allowlist`를 폐기하고 `gateway.standalone`으로 개별 프로필을 분리합니다. 마법사는 설치 코드의 해당 지원을 읽기 전용으로 확인합니다. 지원되면 네 연구 프로필만 standalone, 자체 multiplex=false로 설정하고 개인 default·lab-agent 설정은 쓰지 않습니다.
- 지원되지 않는 구형 Hermes에서 공용 multiplex가 켜졌다면 명확한 호환 오류로 멈춥니다. 폐기된 allowlist나 강제 실행으로 중복 응답 방지를 우회하지 않습니다.
- 자격증명 기록 전에 프로필의 격리 설정을 확인하고, 모든 프로필 구성 후 서비스 시작 전에 네 프로필을 다시 확인합니다. 총괄 전용 시작 스크립트와 연구 프로필 환경에도 multiplex=false를 지정합니다.

## 확인

- Python 전체 무료 회귀 검사: 84 tests 통과(새 격리 검사 9개 포함). 실제 모델 호출 없음.
- 현재 설치된 Hermes의 실제 `profiles_to_serve` 함수를 별도 임시 홈에서 실행: 개인 `default`, `lab-agent`만 공용 경로에 남고 연구 프로필 4개는 제외됨. 실제 Gateway·봇·인증·모델은 시작하지 않음.
- WPF: 최상단 버튼 위치, 접힌 세부 설정, 필수 동의, 실제 버튼 클릭→네 봇 순차 발급→단일 팀 설정 호출, 발급 실패 시 중단, 1단계 비밀번호 연결·로그 미노출을 모의 확인. 화면 렌더링도 확인.
- 설치 흐름 모의 검사 82 assertions, 기록 보존 전환 77, 팀 입력·payload 37, 기본값 19, 재현 가능한 ZIP·추출 마법사 검사 92 assertions 통과. 서로 다른 검사 수를 더해 실제 설치 통과 수로 표현하지 않습니다.
- 기존 서버·봇·토큰·대화는 이번 수정 중 삭제하거나 재발급하지 않았습니다. 개인 config.yaml·인증과 원본 GitHub를 수정하지 않았습니다.

## 미검증

이번 수정에서 새 설치와 실제 모델 S1·S2·S3을 다시 실행하지 않았습니다. 위의 모의·호환성 검사는 실제 설치 완료 영수증이 아닙니다. 사용자가 새 마법사의 버튼으로 진행할 때 현재 설치 지문에 맞는 실제 테스트·감사·첨부 증거가 모두 있어야 사용 준비 완료가 됩니다. 이전 실제 비교의 수리·개입 이력과 사용량은 [0.17.1 기록](verification-0.17.1.md)을 참조하세요.
