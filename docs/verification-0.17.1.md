## 실제 비교 범위

- gpt-6.1-sol 구독 연결, 동일 사용자 요청·수용 기준·공개 원문/합성 입력, 동일 전체 원본 페르소나입니다.
- 포크의 5역할은 집필을 분석에 합쳐 3+1로 비교했습니다. 원래 5역할 성능을 그대로 대표하지 않습니다.
- 작업 재개 기본값은 비교 대상 설정에 포함했습니다. 포크는 최대 5/기본 2, 수정본은 기본 50입니다. 둘 다 2000턴·일시 오류 재시도 100·시도당 3시간으로 구성했습니다. 모든 한도가 동일하다는 뜻은 아닙니다.
- 별도 Mattermost 127.0.0.1:19078·팀별 프로필/작업 보드에서 실제 모델과 독립 실행기를 사용했습니다. 기존 18065 서버는 사용하지 않았습니다.
- 최초 사용자 메시지는 별도 Mattermost에 게시하고 총괄 CLI에 한 번 전달했습니다. 최초 Gateway 멘션 수신 경로는 이 비교로 검증하지 않았습니다.
- S1은 동일 공개 원문 8편을 재사용하는 비교입니다. 외부 검색의 최신성·검색 공급자 가용성까지 평가한 결과가 아닙니다.
- 포크 S2/S3의 수집기 영향 회차는 제외하고 독립 프로필에서 재시험했습니다. 원본 실패·중단 기록은 보존했습니다.

| 시나리오 | 포크 3+1 | 수정본 |
|---|---|---|
| S1 | 중간 감사 통과 뒤 집필 1회 한도·추가 승인 대기, Word 미전달 | 실행 코드·전달 경로 수정 및 완료 커밋 복구 후 Word·근거표 첨부, 재다운로드 해시 확인 |
| S2 | 새 재시험에서도 실행 승인 정책 차단 후 보류, 실제 통계·첨부 없음 | 저장된 코드·근거 재사용, 총괄의 의존성 수정·재배정·독립 재감사 후 Word·통계·그래프·코드 등 18개 첨부. 전체 다운로드를 감사 해시·현재 Git 바이트와 별도 대조 |
| S3 | 새 재시험에서도 블라인드 감사의 commit–파일 해시 연결 근거 부족으로 보류 | 최종 감사·HTML 첨부·재다운로드 확인. 실제 브라우저에서 숫자·단위·출처·버전 확인 |

수정본 S1·S2는 처음부터 자동 완주한 결과가 아닙니다. 실험 중 수리·복구 이력이 있습니다.
S3 수집기는 첨부 확인 후 종료해 마지막 조정기 후처리 종료까지는 관찰하지 못했습니다.
후속 수집기는 모든 모델 프로세스 종료까지 기다립니다. 단일 회차로 통계적 우월성을 주장하지 않습니다.

## 실제 산출물·수리 결과

- S1: Word 23페이지를 읽기 전용 렌더링해 전체 페이지를 확인했습니다. 근거표와 함께 첨부·재다운로드를 확인했습니다. 분할 표의 머리글 등 편집 품질 개선 여지는 있습니다.
- S2: A/B 각각 n=2, 평균 2/6 mg/L, 표본 표준편차 1.4142135623730951/2.8284271247461903, B−A=4입니다. 작성자의 함수와 별개 산술식으로 재계산해 일치를 확인했습니다. 합성 자료의 기술 비교이며 유의성·인과·일반화 결과가 아닙니다.
- S2의 Word 7페이지를 실제 렌더링했습니다. 그래프는 별도 SVG 첨부이며 Word 내부 삽입은 아닙니다. 과거 전달 전 상태 문구가 남아 있어, 전체 요청 완료 여부는 최종 스레드 전달 기록과 구분해야 합니다.
- 감사 이전에 첨부가 있어야 한다는 순환 대기를 제거했습니다. 로컬 최종 파일을 먼저 만들고 독립 감사한 후, 승인된 파일을 수정·변환하지 않고 그대로 전달하며 재다운로드 해시를 검사합니다. 실제 S2 Word의 감사·Git·다운로드 SHA-256은 `1dc2e137df2fc3249d988457d9c366254215e87053b6413511871bab0d894289`로 일치했습니다.
- S3: 실제 브라우저로 HTML의 숫자 6개·mg/L·출처·버전을 확인했습니다. 원본 참조 JSON이 포함되고 외부 스크립트 없이 열립니다.
- 이전 실패·반려·사용 횟수·근거는 보존했습니다. 사람이 감사 pass나 작업 done을 만들어 넣거나 기존 시도 횟수를 초기화하지 않았습니다. S1의 완료 커밋 복구·전달 명령 재실행과 S2의 실행 코드 갱신·서비스 재개는 사람/개발자 개입으로 집계합니다.

## 선택

다음 로컬 후보는 수정본입니다. 기존 3+1과 원본 페르소나를 유지하고, 포크의 Git 작업 보드·독립 실행기·총괄 후속 판단·저장 방식에 버전별 강제 감사와 복구·전달 수정을 결합합니다. 양쪽 페르소나는 동일하게 맞췄으므로 포크 페르소나 교체가 우수하다는 근거는 없습니다.

이번 결과는 **수리·재개를 포함한 산출물 완성 비교**입니다. 수정된 최종 패키지의 새 설치→무수정 자동 완주 인증이 아니며, 설치 마법사에는 이번 실험의 성공 기록을 끼워 넣지 않았습니다.

## 안전·미검증

- 개인 인증은 읽기 전용 중계기로 사용했고 실험 폴더에는 개인 OAuth 토큰이나 갱신 토큰을 복사하지 않았습니다. 실험용 로컬 키만 저장했습니다.
- 최종 대조에서 개인 `auth.json`의 시험 전후 해시는 달랐습니다. 파일 수정 시각은 2026-10-21 18:02:22 KST이고 개인 Hermes도 병행 실행 중이었습니다. 중계 코드에는 쓰기·갱신 동작이 없지만 변경 주체는 확인하지 못했으므로 인증 파일이 완전히 불변이었다고 주장하지 않습니다. 인증 내용을 출력하거나 이전 내용으로 복원하지 않았습니다.
- 초기 Hermes 실행이 기존 실행용 CMD를 동일 내용으로 다시 기록한 흔적은 있습니다. 내용 해시는 동일했고, 이후 실행은 실험용 코드 복사본으로 분리했습니다.
- 모의 검사나 이 비교 결과를 설치 완료 증거 파일로 넣지 않았습니다. 현재 설치 fingerprint에 맞는 실제 S1/S2/S3 증거가 없으면 마법사는 사용 준비 완료로 표시하면 안 됩니다.
- 새 Windows/WSL/Docker 전체 설치, 최초 Gateway 수신, 재부팅 후 실제 서비스 복구, 원격 Windows CI, LiteLLM 실제 호출은 별도 검증이 남아 있습니다.
