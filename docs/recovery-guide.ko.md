# NST 연구팀 실패·재시도 안내 (0.20.0)

우선 기존 서버·프로필·토큰을 삭제하거나 전체 재설치하지 마세요. 같은 입력으로 안전하게 재시도할 수 있는지 먼저 확인합니다.

| 상황 | 조치 |
|---|---|
| Docker 준비 실패 | Docker Desktop Linux 엔진을 켜고 다시 준비 확인. 기존 컨테이너를 일괄 중지하지 않음 |
| Hermes가 있는데 고정 버전 확인 실패 | 0.9.0의 **기존 Hermes 사용**을 명시 선택하고 데이터·코드 경로 확인 후 재조회. 이 모드는 사용자 신뢰 설치의 별도 호환성 검사이며 새 설치 검증을 끄지 않음. 기존 설치를 삭제·다운그레이드하지 않음 |
| 기존 Hermes 모드에서 Gateway 연결 실패 | 실행 중인 프로필 통합 Gateway가 있는지 원래 Hermes에서 확인. 마법사는 기존 Gateway를 자동 시작·중지·재시작하지 않음. 새 연구 프로필이 이미 만들어졌으면 같은 마법사 소유 기록으로만 명시 재시도 |
| `$freshPlan` 변수가 설정되지 않았다는 오류 | 0.8.0의 초기 설치 거부 원인을 가리는 마법사 내부 오류. 수정된 0.8.1 ZIP을 모두 풀고 다시 실행. 이 수정은 기존 설치의 자동 인수나 검증 우회를 제공하지 않음 |
| 서버 설치 도중 실패 | 원래 서버 ID·포트·관리자 계정/암호로 **같은 서버 이어서 설정**. DB·volume 보존 |
| NetBird 공유 실패 | 현재 서버 PC의 NetBird 주소·연결 확인. 마법사는 이전 공개 범위로 롤백하며 실패 시 전환 기록을 남김. 복구 후 동일 입력으로 재시도 |
| 이 PC에서는 되지만 다른 PC에서는 실패 | NetBird의 양쪽 연결과 해당 TCP 포트 정책·호스트 방화벽을 확인. 전체 방화벽 해제나 공유기의 인터넷 포트포워딩은 하지 않음 |
| 사용자 연결 검사 HTTP 401 | 봇 토큰 원문인지 확인. Token ID·봇 ID·관리자 암호는 사용할 수 없음 |
| 채널 검사 HTTP 403/404 | Home Channel ID와 봇의 팀·채널 멤버십 확인. 채널 이름/URL이 아닌 26자리 ID 사용 |
| OAuth 인증·작업 등록 취소 | 본인이 인증/UAC를 승인한 뒤 같은 설정을 다시 진행. 다른 사람 인증값을 복사해 넣지 않음 |
| 봇 발급 재시도 | 원래 봇 이름·표시 이름·설명으로 실행. 기존 봇/토큰 재사용. 다른 사람이 만든 계정은 자동 인수하지 않음 |
| 토큰은 발급됐지만 암호화 파일이 없음 | 중복 발급하지 않고 중단. 관리자 콘솔에서 기록의 `HermesEasySetup/<작업 ID>` 토큰을 확인. 자동 폐기·교체는 없음 |
| compose/소유권/설치 무결성 불일치 | 검증을 끄거나 기록을 지우지 말고 수정 원인을 확인. 사용자 변경을 자동 덮어쓰지 않음 |

서버 공유를 해제하려면 기존 정보를 넣고 이어서 설정에서 **공유 해제**를 선택합니다. 데이터는 남지만 다른 PC의 연결은 끊깁니다.

## 보관·백업 경계

서버 설치 기록은 `%LOCALAPPDATA%\HermesEasySetup\servers\<서버 ID>`에 있고 실제 DB·Mattermost 파일은 Docker named volume에 있습니다. 이 폴더를 복사하는 것만으로 완전한 서버 백업이 되지 않습니다. `database.bin`과 봇 `.bin`은 현재 Windows 사용자 DPAPI에 묶여 있어 다른 PC로 단순 복사하여 복구할 수 없습니다.

이번 버전은 설정 전환 복구·재시도를 지원하며 **자동 DB 백업/새 PC 데이터 복원 UI는 제공하지 않습니다**. 운영 데이터 이관 전에는 DB와 Mattermost 파일의 일관된 백업·복원 계획을 별도로 세워야 합니다. Docker Desktop 초기화, volume 삭제, `.env`/프로필 삭제는 복구 방법이 아닙니다.

진단 자료를 공유할 때 `.env`, `auth.json`, 봇 토큰, 관리자/Dashboard 암호, DPAPI 파일을 포함하지 마세요. 배포 ZIP은 소스 허용 목록으로 만들며 개인 설치 상태·로그·인증을 포함하지 않습니다.
