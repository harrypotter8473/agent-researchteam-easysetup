# 관리자 4단계 — 봇 생성·토큰 발급 검증

검증일: 2026-09-21 / 마법사 0.7.0 / Mattermost 11.11.0 / Bot Control 0.6.2

## 구현 범위

- 기존 관리자 마법사 하단에 별도 동의·암호 입력을 받는 봇 발급 패널 추가.
- 이 마법사의 로컬 배포 기록과 실제 사람 시스템 관리자 인증을 검증한 뒤 봇 생성.
- 일반 봇 역할, 소유자·생성 마커 확인, 기존 팀·채널의 일반 멤버로 연결.
- 공식 API로 토큰 발급, DPAPI 암호화 파일에 원자적으로 보관. 토큰 원문은 진행 이벤트나 결과 JSON에 포함하지 않음.
- 토큰·Home Channel ID 명시적 복사. 마법사를 다시 열어 같은 입력으로 기존 발급 결과 확인 가능.
- 다른 이름의 봇을 추가할 수 있음. 기존 계정 인수, 역할 승격, 기존 토큰 자동 폐기·교체는 하지 않음.

## 실제 Docker 검증

`tests/Run-AdminDockerE2E.ps1 -Apply -WithBotControl -WithBots`로 무작위 이름의 별도 테스트 서버를 생성하여 확인:

1. 최초 관리자·팀·채널 생성, 공개 가입 차단, 정상 사용자 관리자 API 접근 거부.
2. 컨테이너 재시작 후 메시지 영속성 및 재실행 시 동일 관리자·팀·채널 유지.
3. Bot Control 설치·재시작·중복 설치, 업로드 잠금, 일반 멤버·익명·위조 헤더 접근 차단.
4. 서로 다른 봇 2개와 각 토큰 발급. 봇 토큰으로 지정 채널 메시지 작성 성공.
5. 같은 요청 반복과 서버 재시작 후에도 동일 봇·토큰 ID, 봇당 토큰 1개 유지.
6. 봇의 서버 설정·Bot Control 관리 API 접근 403.
7. 봇 생성 기능을 잠시 켠 상태에서도 일반 멤버의 봇 생성·다른 봇 토큰 발급 403.
8. 봇 생성 기능 재잠금, 사람용 Personal Access Token 기능 비활성 유지.
9. CLI stdout/stderr, 상태 JSON, 암호화 파일에서 토큰 평문 유출 없음.

테스트 종료 시 해당 임시 서버의 컨테이너·네트워크·volume과 임시 발급 파일만 정리했다. 이미지 캐시는 유지하며 기존 로컬 Mattermost 및 GB10은 변경하지 않았다. 테스트용 봇·토큰은 실제 사용자에게 사용할 자격 증명으로 남겨 두지 않았다.

## 단위·화면 검증

- `Run-AdminBotTests.ps1`: 입력 검증, 소유자·역할 변경 거부, DPAPI, 저장 파일 덮어쓰기 거부, 생성 응답 유실 복구, 토큰 응답 유실 시 중복 발급 방지, 비활성 토큰 재발급 거부, 생성 설정 복구.
- `Run-CliTests.ps1`: 봇 발급의 `-Apply`, 암호화 입력, transport 경로 제한.
- 관리자 WPF smoke: 새 컨트롤·이벤트, 별도 동의, 결과 라우팅, 완료 전 복사 금지. `-ProbeDocker`는 실제 숨김 worker·Dispatcher 완료까지 확인.
- 기존 설치/보안/CLI/GUI/사용자용 Mattermost/관리자 테스트를 유지한다.

## 남은 범위

현재 테스트 서버 주소는 loopback 전용이다. 다른 PC에서의 NetBird 접속, 실제 사용자용 Hermes 마법사로 연결하여 Bot Control 적용까지 이어지는 전체 시나리오, 운영 배포·백업·복구·배포 패키징은 5단계에서 다룬다. 이 작업은 GitHub push나 실제 GB10 변경을 포함하지 않는다.

토큰 발급 후 로컬 저장 전 중단처럼 원문을 회수할 수 없는 경우에는 중복 발급 없이 멈춘다. 자동 토큰 교체·폐기 UI는 제공하지 않는다. 봇의 설명은 Mattermost 프로필 설명이며 Hermes 역할·메모리 설정과 다르다.
