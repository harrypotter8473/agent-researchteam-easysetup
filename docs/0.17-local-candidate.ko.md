## 확인한 것과 확인하지 못한 것

tests/compare_fork.py는 양쪽 코드를 읽고 같은 미감사 산출물 전달·후속 작업 조건을 검사합니다.
전송은 모의 처리하고 모델은 호출하지 않습니다.
포크는 완료 상태만으로 의존 작업/전달을 허용했고, 후보는 현재 버전 감사가 없으면 차단했습니다.
이는 **감사 통제 차이**이지 S1·S2·S3 연구 품질이나 완주 성능 비교가 아닙니다.

후보의 감사·재시도·설치 판정 단위 검사, 서비스 모의 검사, Windows PowerShell 설치 모의 검사,
원클릭 발급 순서와 WPF/압축 패키지 검사는 [검증 기록](verification-0.17.0.md)을 참조하세요.
실제 로컬 Git push/pull 통합 검사는 이 실행 환경에서 Git의 sh.exe가
NtCreateDirectoryObject / 0xC0000022로 거부되어 진행하지 못했습니다.
이 항목은 통과가 아닙니다. 보안 설정을 우회하거나 호스트 구성을 바꾸지 않았습니다.
Windows 원격 CI 및 실제 설치·모델 S1·S2·S3는 이번에 실행하지 않았습니다.

따라서 **어느 설정이 실제 S1·S2·S3를 더 잘하는지의 승자는 아직 미정**입니다.
모의 결과만으로 포크가 더 좋은 연구 품질을 낸다거나 후보가 실사용 준비 완료라고 주장하지 않습니다.

## 다음 비교 방법

허가된 독립 설치 환경에서 원본 포크와 후보를 서로 다른 서버·프로필·작업 폴더에 준비합니다.
같은 선택 모델, 동일 입력·원문/합성 데이터, 같은 실제 시간·비용 예산을 사용합니다.
자연 사용자 요청으로 실행하고, 사후 평가자에게 버전 이름을 가립니다.

- S1: 근거 충실도·방법/데이터/성과/한계 비교·Word 완성·미확인 명시.
- S2: 재현 가능한 계산·정확한 수치·그래프·독립 재계산·반려 후 수정.
- S3: 참조 결과의 수치 일치·출처/한계·HTML 열람·최종 버전 감사.
- 공통: 완주율, 사람 개입 횟수, 사용량/시간, 무근거 완료, 중복 작업, 재시도, 근거 재사용.

포크 설정이 더 나으면 해당 도구/스킬/검색·메모리 설정을 우리 3+1 역할에 매핑해 반영합니다.
원래 페르소나와 강제 감사는 자동으로 버리지 않습니다.
한 번의 모의 통과를 실제 모델 완주로 대체하거나, 5역할 대 4역할 효과를 설정 차이로 단정하지 않습니다.
