# Mattermost 내부 한국어 작업보드·NST 브랜딩

마법사 3단계의 기본설정 버튼이 `한국어 연구 작업보드`와 `NST Wordmark` 플러그인을 함께 설치합니다.
연구팀이 이미 설치돼 있으면 **설치된 연구팀에 보드·NST만 연결**을 누를 수 있습니다.
이 버튼은 연구 프로필·모델·감사·근거·S1·S2·S3 검증 기록을 교체하거나 재실행하지 않습니다.

## 여는 방법

- Mattermost 왼쪽 채널 목록 위의 **연구 작업보드**, 또는 채널 머리글의 보드 버튼을 선택합니다.
- 작업보드는 팀 내부 화면에서 열립니다. 프로젝트·작업·결과 파일·현재 버전 감사·사용자 확인 요청·읽기 쉬운 실행 기록을 봅니다.
- 보드는 읽기 전용입니다. 승인·추가 자료는 기존처럼 Mattermost에서 총괄에게 전달합니다. 화면 열람이 감사 통과나 작업 승인을 의미하지 않습니다.
- 마법사의 **Mattermost 작업보드 열기**와 작업 폴더의 `Mattermost Research Board.url`도 같은 화면으로 연결됩니다.
- 기존 독립 보드 주소와 `Research Board.url`은 복구용으로 유지됩니다.

## 접근과 연결 보안

Mattermost 로그인, 홈 채널 참여, 명시적 열람 허용 사용자 ID를 모두 검사합니다. 기본 허용자는 마법사에서 선택한 연구 요청자 한 명입니다.
추가 사용자를 허용하려면 시스템 관리자가 플러그인 설정의 허용 사용자 ID 목록을 수정해야 하며, 해당 사용자도 홈 채널에 참여해야 합니다.
봇 계정과 로그인하지 않은 사용자는 차단합니다. 읽기 권한이 작업 배정·문서 수정·감사 승인·도구 실행 권한으로 확장되지 않습니다.

보드 연결 프로그램은 Windows의 127.0.0.1에서만 수신하고 별도 임의 비밀값으로 Mattermost 서버 플러그인만 인증합니다.
Docker Desktop의 호스트 연결을 사용하며, 브라우저에는 연결 비밀값·봇 토큰·모델 인증을 전달하지 않습니다.
서버 플러그인은 지정된 로컬 연결 주소와 네 개의 읽기 전용 보드 API만 사용합니다. 문서 HTML은 실행하지 않고 텍스트로 미리 보거나 파일로 다운로드합니다.
기존 보드가 다시 시작돼 포트가 바뀌면 `dashboard.json`을 다시 읽어 연결합니다.

Windows 로그인 시 보드 연결 작업도 자동 시작됩니다. 개인 Hermes와 연구 실행기는 별도이며, 연결이 끊기면 완료를 가장하지 않고 보드 연결 오류를 표시합니다.

## 자동 설치와 복구

- 자동 적용은 이 마법사가 소유한 로컬 Docker/AMD64 서버만 지원합니다. 외부 서버나 다른 소유자의 컨테이너는 변경하지 않습니다.
- SHA256이 고정된 두 패키지와 연결 프로그램만 설치합니다. 최종 사용자 PC에는 Go·Node가 필요하지 않습니다.
- 플러그인 업로드를 허용하는 동안만 Mattermost 컨테이너를 재시작하고, 설치 후 업로드를 다시 잠가 한 번 더 재시작합니다. 계정·대화·첨부파일 볼륨은 유지됩니다.
- 실행 중인 연구가 없는 때 적용하세요. 재시작 동안 Mattermost 연결은 잠시 끊길 수 있습니다.
- 서버의 서명 필수 정책은 자동으로 해제하지 않습니다. 별도 경로로 설치한 동일 ID 플러그인도 자동 덮어쓰지 않습니다.
- 마법사 소유 기록과 현재 버전이 일치하는 플러그인만 더 높은 고정 버전으로 갱신합니다. 같은 버전의 다른 해시나 이전 버전으로는 자동 교체하지 않습니다. 정상 상태에서 같은 버튼을 다시 누르면 서버를 재시작하지 않습니다.
- 기존 GIST·INFONET 워드마크가 있으면 삭제하지 않고 비활성화해 NST와 충돌하지 않도록 합니다. 다른 플러그인은 보존합니다.
- NST Wordmark는 사용자가 만든 0.1.0 브랜딩입니다. 상단은 NST, 배지는 BETA VERSION으로 표시합니다. 이름표 변경은 Mattermost 제품·라이선스·공식 제휴를 변경하거나 증명하지 않습니다.

연결 상태는 운영 폴더의 `mattermost-plugins/state.json`에, 연결 비밀값은 같은 비공개 폴더의 `bridge.json`에 저장됩니다.
이 폴더는 현재 Windows 사용자와 SYSTEM만 접근하도록 제한합니다. 공개 저장소·진단 자료에는 포함하지 마세요.
적용 실패 시 연구 기록을 삭제하거나 S1을 다시 실행하지 말고, 같은 버튼으로 연결·플러그인 상태를 재확인하세요.

## 개발

플러그인 소스는 `plugins/research-board`에 있고 NST 원본은 `plugins/nst-branding`에 보존했습니다.
`plugins/build.py --go <Go 실행 파일>`이 Linux/AMD64 서버 바이너리를 만들고 결정적인 tar.gz 및 pin을 생성합니다.
무료 검사는 `go test ./server`(플러그인 폴더), `python -m unittest discover -s tests -p 'test_mattermost_*.py'`, `node tests/test_mattermost_plugin_webapp.cjs`입니다.
