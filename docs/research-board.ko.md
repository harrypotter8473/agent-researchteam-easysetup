# 한국어 연구팀 작업 보드 — 0.22.1

## 화면

- 연구 프로젝트 / 설치 검증을 구분합니다.
- 프로젝트는 요청/명시된 제목으로 표시하고 설치 검증은 문헌검토·자료 분석·내부 웹 보고서로 구분합니다. 원래 폴더명·ID·API 경로는 변경하지 않습니다.
- 작업과 총괄 조치를 대기 / 진행 중 / 확인 필요 / 완료 칸에 작은 네모 카드로 표시하며, 상태 변경 시 같은 작업 카드가 해당 칸으로 이동합니다.
- 대기는 아직 시작하지 않았거나 선행 작업을 기다리는 과제입니다. 진행 중은 실제 실행 상태만 표시합니다. 반려·실패·부분 완료·보류·사용자 결정 요청은 확인 필요에 표시하고 구체적 이유는 클릭 상세에서 확인합니다. 감사는 역할별 과제이지 별도의 상태 칸이 아닙니다.
- 카드 앞면에는 '분석 보고서'처럼 짧은 제목만 보입니다. 담당·상태·요약·크기·감사 정보는 클릭 상세에서 확인합니다.
- 카드 최소 높이는 64px입니다. 좁은 화면에서도 네 칸을 세로 목록으로 바꾸지 않습니다. 보드 안에서 가로로 이동하며 각 칸을 확인합니다. 수동 드래그로 상태나 감사를 변경할 수 없는 읽기 전용 화면입니다.
- 클릭하면 맨 위에 줄바꿈되는 저장 요약, 제한 높이의 결과 파일 목록, 접힌 상세 기록을 확인합니다. 제출/조치 당시 요약과 현재 감사 상태를 구분합니다. 요약을 위해 모델을 추가 호출하지 않습니다.
- 새로운 총괄 완료 요약은 안전하게 정제한 최대 4,000자를 보존합니다. 구버전이 이미 잘라 저장한 내용은 복원하지 못하며 상세 원문에서 확인해야 합니다.
- 실무 과제와 실제 총괄 조치 카드를 구분해 셉니다. 총괄의 직접 배정·계획 변경·기준 정리·전달, 백그라운드 후속 판단을 기록합니다.
- 총괄 카드는 영구 활동 원장에서 읽는 관측 기록입니다. 역할 실행기 큐나 감사 승인·사용자 승인으로 쓰지 않으며, 실무 완료·감사 원장에 가짜 항목을 추가하지 않습니다.
- 실행 중인 일·사용자 확인·미해결 실무 과제는 먼저 보이고, 총괄 조치 이력은 최근 순서입니다. 과거의 일시적 실패를 최신 완료 결과보다 위에 고정하지 않으며 삭제하지도 않습니다.
- 실시간 기록은 같은 담당의 연속 행동을 한 묶음으로 접어 표시합니다. 펼치면 시간·실제 행동·결과를 확인합니다.
- 담당 필터는 서버에서 먼저 적용하며 커서 기반 ‘이전 기록 불러오기’로 오래된 조사·감사 활동도 확인합니다.
- 결과 문서·근거는 페이지 맨 아래의 제한 높이 폴더형 목록에 정리합니다. 파일 이름 검색·미리보기·다운로드가 가능합니다.
- 문서의 저장된 버전과 아직 실행 중인 작업은 구분됩니다. 에이전트의 모든 미저장 편집을 실시간 공동편집하는 기능은 아닙니다.
- 화면·상태·안내는 한국어입니다. 논문 제목·파일 이름·기술 식별자는 원문을 유지합니다.

## 운영 정책은 그대로

총괄이 Git 작업 보드에 배정하고 세 역할 실행기가 처리합니다. 전체 기존 페르소나,
버전별 강제 중간/최종 감사와 수정본 재검수, 역할별 저장 권한, 근거 재사용,
모델 및 한도는 변경하지 않았습니다. 심사는 블라인드로 수행합니다.
진행·로그 화면을 추가한 것이며 워크플로우를 고정한 것이 아닙니다.

Mattermost는 같은 스레드에서 짧은 접수·중요 문제·정확한 사용자 결정 요청·최종 파일을 전달합니다.
자동 실행기의 일상적인 진행 상태와 총괄 후속 점검 전문은 웹 보드로 이동합니다.
사용자 결정은 Mattermost를 통해 받습니다. 웹 보드는 읽기 전용이며 감사/승인 버튼으로 우회하지 않습니다.
총괄이 회복 가능한 오류를 검토하는 상태와 실제로 사람의 입력을 요청한 상태는 구분합니다.
연구 총괄의 Mattermost 프로필에서도 기본 도구 진행·중간 응답·추론 표시를 끕니다.
개인 Gateway 및 다른 플랫폼의 표시 설정은 변경하지 않습니다.

## 저장과 보안

완료 작업·문서는 기존 프로젝트 Git의 `.tasks/`와 역할별 출력 폴더를 읽습니다.
공유 로컬 bare 저장소의 최신 커밋을 읽으며 사용자 작업 폴더를 pull/reset하지 않습니다.
진행 중 행동은 연구 런타임의 `activity/*.jsonl`에 생산 프로세스별로 추가 기록합니다.
활동은 기본 100건씩 가져오며 담당·프로젝트·작업 필터를 먼저 적용합니다. 이전 페이지도 같은 조건으로 조회합니다.
오래된 파일·긴 파일의 앞부분도 조회 대상이며, 기록 파일은 자동 삭제하지 않습니다.
파일이 늘어도 매번 원문 전체를 다시 읽지 않도록 Git 객체를 제한된 크기로 묶어 검증하고,
같은 객체의 해시·작은 제어 문서만 용량 제한 안에서 재사용합니다. 파일·작업 버전이 바뀌면
다시 확인하므로 과거 감사 통과를 새 버전에 적용하지 않습니다. 요약에서는 파일 경로 목록보다
저장된 결과 설명을 먼저 보여 줍니다. 이 조회 최적화는 실행·감사·승인 권한을 바꾸지 않습니다.
재시작해도 Git 기록과 활동 파일은 유지됩니다. 장기 보관/압축 정책은 후속 기능입니다.
실행기가 중단되면 재시작 시 미커밋 초안을 지우기 전에 역할별 허용 출력과 실행 시도를
미완료 체크포인트로 저장합니다. 기존 한도·사람 승인·독립 감사 조건은 그대로 유지합니다.
서비스 상태 파일의 일시적 쓰기 실패는 모델 작업을 종료하지 않으며, 서비스 오류의 안전한
분류·코드 위치는 `logs/team-supervisor.jsonl`에 기록합니다. 원시 예외 내용·인증값은 기록하지 않습니다.

보드는 `127.0.0.1`의 임의 포트에서만 열립니다. Host/Origin을 검사하며 외부 사이트의 접근을 차단합니다.
첫 실행 뒤에는 기존 로컬 포트를 사용할 수 있으면 유지합니다. 다른 프로그램이 점유했으면
그 프로그램을 중지하지 않고 새 로컬 포트를 선택하며, Mattermost 안의 보드 주소는 그대로입니다.
일반 출력 파일만 허용하고 경로 탈출·Git 메타데이터·`.env`·심볼릭 링크를 거부합니다.
원시 도구 출력·비밀번호·키·환경 변수·추론은 웹 활동 로그에 복사하지 않습니다.
파일 내용은 텍스트로 미리 보거나 첨부 다운로드합니다. 산출물 HTML을 보드 권한으로 실행하지 않습니다.
이것은 Windows 계정 간 보안 경계를 새로 만드는 OS 샌드박스가 아닙니다.

Hermes가 `--format stream-json`을 제공하면 실제 tool_use/tool_result를 사용합니다.
구버전은 작업·저장 기록을 유지하되 도구별 실시간 관측이 불가능하다고 표시합니다. 없는 행동은 만들어내지 않습니다.
