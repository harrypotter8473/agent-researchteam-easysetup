# NST 0.20.0 실행 구조

개인 Hermes의 공용 Gateway는 유지합니다. 지원되는 Hermes에서는 네 연구 프로필에만 `gateway.standalone: true`, `gateway.multiplex_profiles: false`를 적용해 공용 경로에서 제외합니다. 총괄만 전용 채팅 Gateway로 응답하며 조사·분석·감사는 작업 보드 실행기에서 일합니다. 개인 config.yaml·인증은 변경하지 않습니다. 구형 Hermes에서 이 격리를 지원하지 않는데 공용 multiplex가 켜져 있으면 중복 응답 위험을 우회하지 않고 구체적인 호환 오류를 표시합니다.

## 누가 일을 하는가

사용자는 Mattermost에서 총괄을 멘션하고 원하는 결과물만 말합니다.
총괄은 요청·수용 기준을 파일로 저장하고 Git 작업 보드에 담당자·출력 파일·의존 작업을 배정합니다.
조사, 분석/집필, 감사 실행기는 별도 프로세스입니다. 총괄 내부의 순차 함수 호출로 세 역할을 대신하지 않습니다.
서비스는 실행기를 관리하고, 비공개 총괄 조정기는 완료·실패·반려 결과를 총괄 LLM에 전달합니다.
총괄은 현재 결과를 보고 추가 조사, 대체 원문, 수정, 재감사, 독립 작업 진행 또는 사용자 질문을 결정합니다.
코드는 배정 형식·상태·권한·의존성·감사·한도·저장을 관리하며 연구 판단 자체를 고정 S1 순서로 작성하지 않았습니다.

| 프로필 | 담당 | 실행기가 게시할 수 있는 경로 |
|---|---|---|
| research-lead | 계획·배정·후속 판단·종합 | 보드 명령으로 요청·계획 관리 |
| research-scout | 검색·원문·추출·조사 작성 | notes/, sources/ |
| research-worker | 분석·실험·집필·수정 | paper/, reports/, experiments/, evidence/, claims.md, outline.md |
| research-reviewer | 독립 블라인드 감사 | reviews/ |

각 SOUL.md에는 기존 역할 TXT 전체를 복사했습니다. 별도 실행 스킬은 CLI와 파일 규약을 연결하며 공통 페르소나를 다시 합치지 않습니다.
설치 시 SOUL·스킬·설정 해시를 기록하고 실행 전 변조·누락을 검사합니다.

## 감사와 수정

감사자는 Git, 작업 보드, 이전 심사 기록이 제거된 현재 제출 사본을 받습니다.
요청·수용 기준·근거·실행 코드·결과는 보존합니다. 문서 본문 자체에 들어 있는 신원을 완전히 익명화하는 기능은 아닙니다.
필수 범위는 요청 충족, 출처와 주장 지원, 방법·핵심 수치 재계산, 문서 내 일관성, 불확실성입니다.
논문급 독창성·문체 평가는 명시적으로 요청한 경우만 필수입니다.

감사 결과는 pass/reject/unverifiable와 위치·근거·수정 요구·차단 여부를 담은 JSON입니다.
실행기가 입력 파일 해시와 생산 작업 버전을 결합한 영수증을 만듭니다.
감사 작업의 done과 감사 pass는 다릅니다. 현재 버전 감사 통과가 없는 후속 작업 및 최종 전달은 차단합니다.
수정은 작성 담당의 새 작업으로 하고 새 감사로 확인합니다. 관련 없는 독립 작업은 계속할 수 있습니다.

## 도구·권한·모델

포크의 Hermes 도구를 사용합니다. 검색·원문 읽기·터미널·파일 도구를 이용하며 도구별 외부 서비스 가용성은 설치 PC에서 확인해야 합니다.
조사자는 저장된 자료와 메모리를 재사용하고, 감사자는 메모리·이전 세션 검색을 사용하지 않습니다.
분석자의 LaTeX 검사 스킬은 해당 작업에만 선택합니다.

봇 토큰은 역할 실행기에 분리해서 전달하고 모델 에이전트 자식 프로세스에는 넘기지 않습니다.
설치된 runtime 폴더 권한은 현재 Windows 사용자와 SYSTEM으로 제한합니다.
게시 경로 검사와 블라인드 사본은 **애플리케이션 통제**입니다. 같은 Windows 계정으로 실행하는 임의 터미널 코드에 대한 OS 보안 격리는 아닙니다.
총괄의 일반 publish 명령으로 감사 영수증·원장·완료 상태를 만들어 넣을 수 없습니다.

기본은 기존 Hermes Codex 연결과 설치 중 선택한 모델입니다. 모델을 임의로 바꾸거나 인증을 패키지에 복사하지 않습니다.
선택적 LiteLLM 경로는 공개 등급별 모델 정책을 사용합니다. 비공개 자료를 로컬 모델 없이 클라우드로 우회하지 않습니다.
직접 Codex 연결은 공개 자료에 한정합니다.

## 파일과 대화

- 논문/프로젝트: 선택한 작업 폴더의 프로젝트별 저장소.
- 일반 보고서: reports/ 공유 저장소의 요청별 하위 폴더.
- 비공개 로컬 Git 원본: RuntimeRoot/research/boards/.
- 실행기 사본: RuntimeRoot/research/work/<role>/.
- 작업·결과·해시 원장: 각 저장소의 .tasks/, .tasks/attempts/, .tasks/ledger.jsonl.
- 감사 영수증: .tasks/audits/. 결과 파일: notes/, reports/, evidence/ 등.
- 서비스 로그: RuntimeRoot/research/logs/. 상태: service-status.json.
- 실제 설치 검증: live-test.json, validation-history/, 작업 폴더의 _validation-<지문>/.
- 총괄 연결 오류: RuntimeRoot/research/run/lead-coordinator-errors.json.

Mattermost는 사용자 대화와 상태·첨부 표시용입니다. 역할 봇의 글을 서로 읽고 호출하는 메시지 큐가 아닙니다.
총괄만 사용자 멘션을 받고, 총괄 조정기만 보드의 다른 역할 결과를 관찰합니다.
진행 글과 결과는 요청의 같은 스레드에 남깁니다.
총괄은 현재 작업, 문서 경로, 실패 원인, 다음 조치/필요한 사용자 입력을 보고합니다.

## 한도와 오류

기본은 2000턴/시도, 최대 50시도/작업, 일시적 모델 오류 100회, 180분/시도입니다.
시간은 마법사에서 30~720분으로 선택합니다. 이 값은 금액·토큰 예산 보장을 뜻하지 않습니다.
부분 자료·체크포인트를 보존하며 반복 입력을 줄입니다.
총괄 후속 호출의 일시적 오류는 저장된 횟수와 backoff로 재시도합니다.
인증·정책 오류는 무작정 반복하지 않고 오류 파일과 사용자 조치를 남깁니다.
해결 후 조정기의 --retry-paused로 명시적으로 재개할 수 있습니다. 기존 보드와 이벤트 커서는 유지합니다.
사용자 승인이 필요한 실험의 중간 중단은 자동 승인으로 간주하지 않습니다.

## 완료 판정

실제 설치 프로필로 S1 문헌검토 Word, S2 합성 CSV 분석, S3 내부 HTML 보고서를 수행합니다.
총괄이 업무 계획을 정하고 설치된 실행기가 수행합니다. 고정 모의 답변은 실제 검사에 쓰지 않습니다.
네 역할 작업·원장·중간/최종 감사·출력·첨부 재다운로드, S2 재계산, S3 임시 localhost 열람이 모두 필요합니다.
S3 임시 열람 검사는 상시 웹 서버 배포 시험이 아닙니다.
코드·모델·프로필 지문이 달라지면 이전 통과 결과를 재사용하지 않습니다.
이 검증은 실제 모델을 쓰지만 최초 사용자 Mattermost 멘션을 포함하는 별도 종단간 시험을 대체하지 않습니다.
